## What I verified
(Tests run, hand calculations compared with the app, checks on the data.)
- M0: counted rows, blanks, negatives, currencies and statuses with a short stdlib script. No tests exist yet.
- M1: `build_summary` compared with an independent exact-decimal calculation on the real CSV (all 3 currency totals and 9 currency-and-status rows matched). Saved tests: 3 passed (hand-calculated frame, missing PO and approver, `/summary` on the real data). Not done: breaking the code on purpose to confirm tests fail, and a test that startup fails on a missing data file.
- M2: plan checks tried on 9 hand-made plans (5 rejected, 4 accepted, as expected). All 10 prompt examples parse as valid plans. 7 real questions run against `qwen2.5:7b-instruct` for each prompt version (v1 to v3). The three error paths (Ollama unreachable, timeout, unknown model) each produce a readable `LLMError`. All of this was run by hand. No saved tests exist for `plan.py` or `llm.py` yet. Plan accuracy is not measured: 7 questions, tuned on.
- M3: 12 tests pass (policy text is verbatim, the prompt menu matches the policy ids, validation reports bad column, value, operator and section together, the currency repair, five execution cases against hand-calculated frames). The test expectations were checked first with a separate pandas calculation. On real data: filter counts match the M0 profile, sums match `/summary`, a count by approver adds up to 140 including the missing group, and rows convert to JSON. Not done: the validator and the executor are not yet connected to the model (that is the pipeline), and the retry on a rejected plan is not built.
- M4: 33 tests pass (verifier checks, fallback passes its own verification on a real top-5 result, rendered rows, six pipeline cases with a fake model, `/ask` contract, out-of-scope decline, 422 and 503, the `.env` reader). Live, with `qwen2.5:7b-instruct`: 9 questions read against the data (one wrong top-5 answer found and fixed by the hybrid), then the real pipeline on 3 questions, then a real `uvicorn` server with curl on `/summary`, `/ask` and an empty question. Not done: an eval set (so answer quality is not measured), the lead sentence can still be misleading, and numbers written as words or rounded are not recognised.
